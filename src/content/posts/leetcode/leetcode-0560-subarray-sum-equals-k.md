力扣第 560 题：给一个整数数组 `nums` 和一个整数 `k`，统计和为 `k` 的连续子数组有多少个。`nums = [1,1,1]`、`k = 2` 时答案是 2，`nums = [1,2,3]`、`k = 3` 时也是 2。

这题的坑在于 `nums[i]` 可以为负数。看到「连续子数组求和」，很容易想到前面的滑动窗口，但这题用不了。

## 为什么滑动窗口失效

第 3 题、第 438 题的窗口能滑动，靠的是一个前提：窗口往右扩，和会变大；窗口收缩，和会变小。有了这个单调性，才知道什么时候该扩、什么时候该缩。

这题有负数，前提不成立了。窗口扩进来一个负数，和反而变小。

拿 `nums = [1,-1,1]`、`k = 1` 试：暴力解数出来是 3 个（`[1]`、`[-1,1]`、`[1]` 中的最后一个）。我按「和大于 k 就缩左边」写了滑窗，结果是 2，漏了一个。

问题出在窗口扩到 `[1,-1]` 时和是 0，比 `k` 小，按规则该继续扩；但扩到 `[1,-1,1]` 和是 1，就停在这里了，中间 `[-1,1]` 这个答案从来没被单独看待过。滑窗只能保证「当前窗口」的性质，没法枚举所有窗口。

**规律**：全正数的连续区间问题用滑动窗口（比如第 209 题）；有负数就必须用前缀和。

## 前缀和

`pre[i]` 表示前 `i` 个数的和，`pre[0] = 0`：

```
nums:    1   2   3
pre:   0   1   3   6
```

那么从下标 `j` 到 `i-1` 这一段的区间和，就是两个前缀和相减：

```
nums[j..i-1] 的和 = pre[i] - pre[j]
```

要这段和等于 `k`，就等价于：

```
pre[i] - pre[j] = k
pre[j] = pre[i] - k
```

换成一句话：**扫到 `pre[i]` 时，看它前面有几个前缀和等于 `pre[i] - k`，就有几个子数组以 `i` 结尾且和为 `k`。**

这就是第 1 题两数之和的思路，只不过那题要返回下标，这题要数个数。

注意 `pre` 数组长度是 `n + 1` 而不是 `n`，多的那一个 `pre[0] = 0` 代表「一个数都没取」的空前缀。少了它，从下标 0 开始的子数组就数不到。

## 方案一：枚举起点和终点 $O(n^2)$

```cpp
class SolutionBrute {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = (int)nums.size();
        int count = 0;
        for (int i = 0; i < n; i++) {
            int total = 0;
            for (int j = i; j < n; j++) {
                total += nums[j];          // 边加边判断
                if (total == k) count++;
            }
        }
        return count;
    }
};
```

内层循环不是先求和再比，而是边加边比，省掉了每次重新求和的开销。这个方案当对拍的标准答案。

## 方案二：前缀和数组 + 双层循环 $O(n^2)$

先算好整个前缀和数组，然后枚举所有 `(j, i)` 组合，用减法求区间和。

```cpp
class SolutionPrefix {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = (int)nums.size();
        vector<int> pre(n + 1, 0);           // 长度 n+1，pre[0] = 0
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];

        int count = 0;
        for (int i = 1; i <= n; i++)
            for (int j = 0; j < i; j++)
                if (pre[i] - pre[j] == k) count++;
        return count;
    }
};
```

- **`pre` 长度是 `n + 1`**：`pre[i]` 对应前 `i` 个数，所以下标范围是 `0` 到 `n`
- **`pre[i + 1] = pre[i] + nums[i]`**：注意两边下标错开一位，`nums` 的第 `i` 个进了 `pre` 的第 `i+1` 格
- **区间和是 $O(1)$**：不用重新累加，减一下就出来了

虽然时间还是 $O(n^2)$，但它把「区间和」变成了两次数组访问。方案三只需要在此基础上换掉内层循环。

## 方案三：前缀和 + 哈希计数 $O(n)$（提交版）

方案二的内层循环在问：「前面有几个 `j` 满足 `pre[j] == pre[i] - k`？」这个问题用哈希表一次就能回答。

`cnt` 记录每个前缀和出现了几次：

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> cnt;
        cnt[0] = 1;                             // 空前缀
        int pre = 0, ans = 0;
        for (int x : nums) {
            pre += x;
            auto it = cnt.find(pre - k);        // ① 只查，不插入
            if (it != cnt.end()) ans += it->second;
            cnt[pre]++;                         // ② 写入，[] 正合适
        }
        return ans;
    }
};
```

因为只往前扫一遍，不需要把整个 `pre` 数组存下来，累加一个变量 `pre` 就够。

### cnt[0] = 1 是干什么的

`cnt` 一开始放一条 `{0: 1}`，代表「空前缀出现过 1 次」。这是为了处理「从下标 0 开始的子数组」。

比如 `nums = [1,1,1]`、`k = 2`，第二段 `[1,1]` 就是从 0 开始的，它的 `pre[j]` 是 `pre[0] = 0`。如果表里没有 0 这一条，这个答案就数不到。

实测：有 `cnt[0] = 1` 时答案是 2（正确），去掉这一行答案是 1，少了从头部开始的那一个。

### 先查后记，顺序不能反

```cpp
auto it = cnt.find(pre - k);   // ① 查
if (it != cnt.end()) ans += it->second;
cnt[pre]++;                     // ② 记
```

必须先查再记。如果先记，当前这个 `pre` 已经进表了，它可能被自己查到，等于把「当前元素自己」当成一个和 `k` 相等的子数组数进去。

这个问题在 `k = 0` 时最明显。用 `nums = [1,-1,0]`、`k = 0` 实测：先查后记得 3（正确），先记后查得 6，翻了一倍。

### 走一遍

`nums = [1,1,1]`、`k = 2`：

```
cnt={0:1}
x=1  pre=1  查 -1：没有          cnt[1]=1
x=1  pre=2  查  0：1 次 → ans=1  cnt[2]=1
x=1  pre=3  查  1：1 次 → ans=2  cnt[3]=1
```

### 查询用 find，写入用 []

`unordered_map` 的 `operator[]` 有一个容易忽略的行为：**键不存在时会自动插入一条 `{key, 0}` 再返回 0**。

```cpp
m.find(99) 之后 size=1    // 没找到，表没变
m[99]      之后 size=2    // 悄悄插入了一条
```

在这个方案里，用 `cnt[pre - k]` 查询不会算错答案（不存在时得到 0，加到 `ans` 上还是 0），但会往表里塞很多用不上的键。数据量大的时候既占内存又拖慢哈希。

所以分工很清楚：**查询一律用 `find()` 或 `count()`，写入才用 `[]`**。第 1 题两数之和讲过同一个坑。

`it->second` 里的 `first` 是键、`second` 是值，这是 `pair` 的两个成员，迭代器指向它。

## 三个方案对比

| 方案 | 区间和怎么算 | 时间 | 额外空间 |
| --- | --- | :---: | :---: |
| 一 | 边加边比 | $O(n^2)$ | $O(1)$ |
| 二 | `pre[i] - pre[j]` | $O(n^2)$ | $O(n)$ |
| 三 | 哈希查 `pre - k` 出现过几次 | $O(n)$ | $O(n)$ |

## 溢出检查

`n` 最大 $2 \times 10^4$，`nums[i]` 绝对值最大 1000，所以前缀和绝对值最大约 $2 \times 10^7$。`pre - k` 最大约 $3 \times 10^7$，`int` 上限是 $2.1 \times 10^9$，够用，不需要 `long long`。

答案个数最多是 $n(n+1)/2 \approx 2 \times 10^8$，也在 `int` 范围内。

## 这题用到的 C++ 写法

- **`unordered_map<int, int> cnt`**：键是前缀和，值是出现次数。这题要计数，所以用 map 而不是 set
- **`cnt[0] = 1`**：给「空前缀」留一条记录，从下标 0 开始的区间才数得到
- **`find()` 查询、`[]` 写入**：`[]` 查不存在的键会插入，查询场景有副作用
- **`auto it = ...; it->second`**：迭代器指向键值对，`first` 键、`second` 值
- **`pre` 数组长度是 `n + 1`**：前缀和的经典约定，`pre[0]` 单独表示空前缀

前缀和这个工具值得单独记一下：只要是「连续区间求和」，而且数组里有负数或者出现在子数组之外的变形，都可以先想前缀和。
