## 武器一：哈希表（空间换时间）

哈希表的用处很直接：把需要 $O(n)$ 线性扫描的查询操作降到 $O(1)$。但这 3 道题考的切入点完全不同。

### 1. 两数之和：不要等存完再查
最直观的想法是先把所有数放进哈希表，第二遍再去查 `target - nums[i]`。但其实只要「边走边查」：
每走到一个数，先看哈希表里有没有它的互补数；有就直接返回下标，没有再把自己写进表里。

这样只需一次遍历，还顺便避开了「同一个数被用两次」的边界判断。

### 2. 字母异位词分组：设计组的“身份证”
异位词的特点是字母组成完全一样、只是顺序乱了。要把它们分到同一组，关键是造一个唯一的键（Key）：
- **方法 A（字符排序）**：把 `"eat"` 排序成 `"aet"`，作为 `unordered_map<string, vector<string>>` 的 Key。
- **方法 B（26位计数数组）**：对只有小写字母的场景，统计 26 个字母频次拼成签名，避免排序。

写 C++ 时最容易混淆的是二维容器类型 `vector<vector<string>>`：外层存的是动态行，每组的长度可以完全不同，并不是固定大小的静态二维数组。

### 3. 最长连续序列：只从段头开始数
题目强行要求 $O(n)$，排除了 $O(n \log n)$ 的排序解法。
改用 `unordered_set` 存所有数后，如果每个数都往后试探 `x+1, x+2...`，最坏情况依旧会退化成 $O(n^2)$。

这里的破局关键是一行判断：
```cpp
if (!num_set.count(x - 1)) {
    // 只有当 x - 1 不存在时，x 才是连续段的起点！
    // 此时才往后遍历连续长度
}
```
跳过所有“段中”和“段尾”的数字，每个连续段只在起点被遍历一次，总耗时牢牢收敛在 $O(n)$。

## 武器二：双指针（单调性与区间收缩）

当数据有序，或者问题天然具备单调性时，双指针可以在 $O(1)$ 额外空间下把 $O(n^2)$ 的枚举空间剪枝到 $O(n)$。

### 1. 盛最多水的容器：对撞指针与短板淘汰
左右两根指针分别放在最左端和最右端。面积公式是：
$$\text{Area} = \min(h[l], h[r]) \times (r - l)$$

为什么每次一定要移动较短的那根指针？
因为向内移动指针，宽度 $(r - l)$ 注定变小。如果移动高板，新高度顶多等于短板，面积必然缩水；翻盘唯一的可能，就是移掉短板去赌下一个更高的板。

### 2. 移动零：快慢指针原地修改
这题要求 $O(1)$ 空间原地操作。
维护一个慢指针（记录下一个非零元素该写入的位置），快指针一路往前扫：
- 扫到非零数，就把它写到慢指针位置（或交换），慢指针前移；
- 扫完之后，慢指针后面的位置全部补零。

也是在这道题里，最直观地体现出 C++ 引用传参的意义：函数签名里的 `vector<int>& nums` 是直接操作调用方原数组的别名，如果漏写 `&` 就会在传值副本上白忙活一场。

## C++ 解题的核心体会与避坑点

1. **容器选型**：只要 $O(1)$ 快速查找，无脑选 `unordered_map` / `unordered_set`；只有需要维护元素有序、或者频繁查找前驱后继时，才考虑红黑树底层的 `map` / `set`。
2. **传参规范**：`vector`、`string` 等大对象作为函数入参时，只读场景一律写 `const&`（如 `const string& s`），避免无谓的内存深拷贝拖慢执行速度；原地修改场景显式加 `&`。
3. **动态二维容器**：熟练掌握 `vector<vector<T>>` 的逐行动态扩展与 `push_back`，行长可以不同，比 C 风格手管指针既安全又灵活。
